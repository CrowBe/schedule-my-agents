# Site-local standard TLS client

This package compiles **Go 1.27.1's standard `crypto/tls`, `crypto/x509` and `net/http`** to WebAssembly. No third-party TLS protocol implementation, certificate-verification bypass, proxy or additional deployment is used. JavaScript connects a raw TCP stream to one validated public IP; Go supplies SNI, certificate-chain/validity/hostname verification, TLS 1.2/1.3 and HTTP response parsing. Application bytes are withheld until the handshake succeeds.

`main.go` is our small stream bridge. `wasm-exec.cjs` and `GO-LICENSE` are verbatim from the checksum-verified official Go distribution. Go runtime source and public API: https://go.dev/dl/ and https://pkg.go.dev/crypto/tls . The official Linux amd64 archive SHA-256 used here is `63d339f0da5ab53635a56f2490a7984dfe12dfcff22ad749f63edaf590168445`.

The checked-in binary allows ordinary Site/CI builds without installing Go. Rebuild with `bash scripts/build-tls.sh /path/to/go1.27.1/bin/go`, then verify the security tests. Keep the runtime shim and binary on the same toolchain release. This adds about 7.5 MiB uncompressed / 2.1 MiB gzip to deployment. Go TLS is established software; this WASM integration is new and its tests are not an independent security audit.

`roots.pem` is public CA material from Node v24.14.0's bundled `node:tls.rootCertificates`, extracted on 6 October 2026. It contains no private keys. Its SHA-256 is `1ce54871c3e0e16c534d4cf464847113d55412fe48c3d5d881c600dd6932debd`. Review trust-store and Go security updates together; the snapshot does not automatically follow platform trust changes. Test roots are passed only to the isolated TLS harness; production always uses this fixed bundle.

Bounds: one attempt has ten seconds including DNS/TLS/read; plaintext request at most 256 KiB, encrypted response/handshake at most 128 KiB, one transport chunk at most 64 KiB, decoded response at most 4 KiB. Redirect/non-success responses and compressed bodies fail closed. No session cache, 0-RTT, connection reuse or callback-IP caching is enabled. DNS A/AAAA answers are all validated on each attempt and a literal address is passed to `cloudflare:sockets` with native TLS disabled. Unsupported address families/ranges fail closed. Cloudflare itself may refuse some otherwise-public socket destinations, including its proxied IPs; that is an availability limitation, not a reason to fall back to unchecked fetch.

`npm test` exercises real TLS and Workers/WASM locally; `node scripts/probe-direct-tls.mjs` is a manual public-network test that sends only a synthetic message to httpbin.org. A hosted Site proof and a real ChatGPT subscription remain separate acceptance checks. Event discovery stays empty until the later signed delivery slice is ready.
